# XMind 测试用例模板

本文件用于补充 `SKILL.md` 中的测试用例结构和写作规范。需要检查用例颗粒度、补充场景矩阵或设计 XMind 树结构时读取。

## 标准树结构

多端需求在 XMind 中优先按端展示：

```text
项目名称（根主题）
├── iOS
│   ├── 入口
│   │   ├── 测试目的：验证首页顶部搜索入口按配置正常展示
│   │   │   └── 前置条件：后台已开启首页搜索入口配置
│   │   │       └── 测试步骤：
│   │   │           1、进入 iOS 端首页
│   │   │           2、查看页面顶部搜索区域
│   │   │           └── 预期结果：
│   │   │               1、首页加载完成
│   │   │               2、展示搜索框、购物车和消息入口
│   │   └── 测试目的：验证点击搜索入口进入搜索页
│   └── 异常场景
├── Android内发包
│   └── 入口
└── 小程序
    └── 入口
```

未显式提到端时，仍可沿用旧版结构：

```text
项目名称（根主题）
├── 模块一
│   ├── 测试目的：验证首页顶部搜索入口按配置正常展示
│   └── 测试目的：验证选购页顶部搜索入口按配置正常展示
└── 模块二
```

不输出用例编号、优先级、标签或备注节点。`测试步骤` 和 `预期结果` 都是单个 XMind topic，步骤和结果以节点标题内多行文本展示。

## JSON 到 XMind 映射

### 多端结构

| JSON 字段 | XMind 节点 |
| --- | --- |
| `project_name` | 根主题 |
| `platforms[].name` | 一级端分组 |
| `platforms[].modules[].name` | 端下业务模块 |
| `cases[].title` | 不输出，仅用于 JSON 可读性 |
| `cases[].purpose` | `测试目的：...` |
| `cases[].prerequisites` | `前置条件：...`；为空时输出 `前置条件：无` |
| `cases[].steps` | `测试步骤：` 节点标题内的多行序号列表 |
| `cases[].expected` | `预期结果：` 节点标题内的多行序号列表 |

| JSON 字段 | XMind 节点 |

## 多端拆分规范

当需求正文显式提到端名时，必须遵循：

- 先按端分组，再在端下拆业务模块。
- 不同端的 case 不能合并成一条，即使验证目标相同。
- 共性功能也要分别出现在每个显式端下。
- 同一需求里若同时提到 `Android内发包`、`Android外发包` 和笼统 `Android`/`安卓`，则笼统 Android 场景默认分别落到内发包和外发包。

标准端标签：

- `iOS`
- `Android内发包`
- `Android外发包`
- `Android`
- `小程序`
- `H5`

## 测试目的规范

测试目的应满足：

- 一句话说明验证点。
- 包含被测对象、所属端和预期行为。
- 避免同时验证多个不相关功能。
- 在 XMind 中作为用例的直接主题，不再额外包一层用例标题。

推荐：

```text
测试目的：验证 Android外发包首页搜索框暗纹词每 3 秒轮播循环展示
```

避免：

```text
测试目的：测试暗纹词
测试目的：验证 iOS/Android/小程序搜索入口展示一致
```

## 前置条件规范

前置条件应说明执行用例前必须满足的环境、账号、配置或数据状态。

推荐：

```text
前置条件：Android内发包已开启灰度搜索入口配置，算法接口正常返回
```

没有前置条件时统一输出：

```text
前置条件：无
```

## 测试步骤规范

步骤应满足：

- 每一步是可执行动作。
- 包含必要的端、页面、入口、账号、配置或数据条件。
- 不把预期结果混在步骤里。

推荐：

```text
测试步骤：
1、打开小程序首页并下拉刷新
2、查看页面顶部搜索区域
└── 预期结果：
```

避免：

```text
1、看页面
2、验证 iOS 和 Android 都正常
```

## 预期结果规范

预期结果应满足：

- 与步骤序号或关键动作对应。
- 明确可观察现象。
- 避免只写“正常”“正确”“符合预期”。

推荐：

```text
预期结果：
1、小程序首页加载完成
2、顶部展示搜索框，且右侧按钮不被遮挡
```

避免：

```text
正常
符合预期
```

## 测试场景矩阵

默认覆盖：

| 维度 | 示例 |
| --- | --- |
| 正常流程 | 搜索入口正常展示，点击后进入搜索首页 |
| UI 展示 | 文案、图标、按钮、空态、加载态、错误态 |
| 交互行为 | 点击、输入、清空、返回、刷新、重复点击 |
| 业务规则 | 暗纹词轮播、配置开关、生效条件、排序规则 |
| 数据场景 | 空数据、单条、多条、大量、重复、异常字段 |
| 网络接口 | 成功、失败、超时、弱网、断网、重试 |
| 缓存逻辑 | 首次进入、有缓存、缓存过期、清除缓存 |
| 边界值 | 0、1、最大值、超长、特殊字符 |

按需覆盖：

| 维度 | 适用情况 |
| --- | --- |
| 权限角色 | 涉及登录、会员、角色、后台配置 |
| 兼容性 | 涉及 iOS、Android、H5、小程序、浏览器 |
| 并发一致性 | 涉及订单、库存、状态同步、多端操作 |
| 安全风控 | 涉及敏感词、越权、注入、隐私、支付 |
| 埋点日志 | 需求提到曝光、点击、转化或数据分析 |

## 完整用例示例

### iOS 端 UI 展示

```text
iOS
└── 入口
    └── 测试目的：验证 iOS 端首页搜索入口正常展示
        └── 前置条件：后台已开启 iOS 首页搜索入口配置
            └── 测试步骤：
                1、打开 iOS 端 App 并进入首页
                2、查看页面顶部搜索区域
                └── 预期结果：
                    1、首页加载完成
                    2、顶部展示搜索框、购物车入口和消息入口，布局不遮挡页面内容
```

### Android外发包配置和轮播

```text
Android外发包
└── 暗纹词
    └── 测试目的：验证 Android外发包搜索框暗纹词每 3 秒轮播展示
        └── 前置条件：后台已配置 3 条暗纹词；算法接口正常返回
            └── 测试步骤：
                1、进入 Android外发包首页
                2、查看搜索框暗纹词
                3、等待 3 秒
                4、再次查看暗纹词
                └── 预期结果：
                    1、首页加载完成
                    2、展示第 1 条暗纹词
                    3、等待期间页面无卡顿或闪烁
                    4、暗纹词切换为下一条，并按配置循环展示
```

### 小程序异常和缓存

```text
小程序
└── 异常场景
    └── 测试目的：验证小程序接口异常时搜索入口展示缓存数据
        └── 前置条件：本地已有上一次成功获取的搜索入口缓存
            └── 测试步骤：
                1、有网条件下打开小程序，确认搜索入口正常展示后退出
                2、阻断搜索配置接口返回
                3、重新打开小程序首页
                └── 预期结果：
                    1、搜索入口展示成功并写入缓存
                    2、接口请求失败
                    3、页面展示上一次成功获取的缓存数据，并不出现空白或崩溃
```

## 需求片段到用例树示例

需求片段：

```text
iOS、Android内发包、Android外发包和小程序首页顶部新增搜索入口。搜索框展示暗纹词，暗纹词由算法接口返回，每 3 秒轮播。接口异常时优先展示缓存，无缓存时展示兜底文案。点击搜索入口后进入搜索首页。
```

```text
搜索入口测试用例

│   ├── 暗纹词
│   │   ├── 测试目的：验证 iOS 暗纹词接口返回后正常展示
│   │   └── 测试目的：验证 iOS 暗纹词每 3 秒轮播
│   └── 异常场景
├── Android内发包
│   ├── 入口
│   ├── 暗纹词
│   └── 异常场景
├── Android外发包
│   ├── 入口
│   ├── 暗纹词
│   └── 异常场景

    ├── 入口

    └── 异常场景
```
